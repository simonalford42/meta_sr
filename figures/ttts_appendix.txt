\subsection{Allocating reevaluations with top-two Thompson sampling}
\label{app:ttts}

Choosing which programs to reevaluate is an instance of \emph{best-arm identification} (BAI), the pure-exploration form of the multi-armed bandit problem \citep{bubeck2009pure,audibert2010best}. Each program in the archive is an arm, and running a program on one more evaluation seed is a pull that returns a noisy fitness. Unlike in the classic bandit setting, the fitness observed during reevaluation is not a reward to be maximized. The only goal is to spend the measurement budget so that the program with the highest mean fitness can be identified. We allocate reevaluations with top-two Thompson sampling (TTTS) \citep{russo2020simple}, a simple Bayesian algorithm for BAI with one tuning parameter $\beta \in (0,1)$. Under TTTS, the posterior probability that the best arm is misidentified decays exponentially in the number of measurements. Asymptotically, it decays at the fastest rate achievable by any allocation rule that gives a fraction $\beta$ of the measurements to the best arm. With the default $\beta = 1/2$, this rate is within a factor of two of the optimal rate over all allocation rules \citep{russo2020simple}. \citet{shang2020fixed} also prove $\beta$-optimal sample complexity for TTTS on Gaussian bandits in the fixed-confidence setting.

TTTS modifies Thompson sampling (TS) \citep{thompson1933likelihood}. TS measures each arm with the posterior probability that it is the best arm: it draws one sample of all arm means from the posterior and measures the arm whose sampled mean is largest. TS is designed to maximize cumulative reward and is asymptotically optimal for that objective \citep{kaufmann2012thompson}. For the same reason, it is a poor fit for BAI. Once the posterior concentrates on one arm, TS measures that arm almost exclusively. The arms competing with it then get too few measurements to be ruled out, so the posterior converges slowly \citep{russo2020simple}. TTTS fixes this by forcing part of the budget onto the strongest challenger to the current favorite. Let $\mathcal{D}$ denote the observations collected so far. One step of TTTS is:
\begin{enumerate}
    \item Draw $\tilde\theta \sim p(\theta \mid \mathcal{D})$ and let $I = \arg\max_i \tilde\theta_i$.
    \item With probability $\beta$, measure arm $I$.
    \item Otherwise, repeatedly draw $\tilde\theta' \sim p(\theta \mid \mathcal{D})$ until $J = \arg\max_i \tilde\theta'_i \neq I$, then measure arm $J$.
    \item Add the new observation to $\mathcal{D}$.
\end{enumerate}
Setting $\beta = 1$ recovers TS. For $\beta < 1$, even when the favorite $I$ has posterior probability close to one, a fraction $1-\beta$ of the measurements still goes to the arms most likely to overtake it.

We model the fitness from one seed of program $i$ as $y = \theta_i + \varepsilon$, where $\theta_i$ is the program's true mean fitness and $\varepsilon \sim \mathcal{N}(0, \sigma^2)$ is noise with a known level $\sigma$ shared by all programs. Suppose program $i$ has been run on $N_i$ seeds with mean fitness $\mu_i$ (i.e., $\mu_i = \hat{J}[\pi_i]$ and $N_i = N[\pi_i]$). Under a flat prior, the posterior is $\theta_i \sim \mathcal{N}(\mu_i, s_i^2)$ with $s_i = \sigma / \sqrt{N_i}$, independently across the $A$ programs in the archive. Instead of simulating the steps above, we compute the probability that TTTS measures each arm exactly. The probability that TS selects arm $i$ is the posterior probability that $i$ is the best arm:
\begin{equation}
    \alpha_i = \Pr\Big(\theta_i = \max_j \theta_j\Big)
    = \int_{-\infty}^{\infty} \frac{1}{s_i}\, \phi\!\left(\frac{x - \mu_i}{s_i}\right) \prod_{j \neq i} \Phi\!\left(\frac{x - \mu_j}{s_j}\right) dx,
\end{equation}
where $\phi$ and $\Phi$ are the standard normal density and CDF. Each $\alpha_i$ is a one-dimensional Gaussian expectation, which we evaluate with 64-node Gauss--Hermite quadrature. The computation is done in log space: we sum $\log\Phi$ terms and combine quadrature nodes with a log-sum-exp, so the product does not underflow when the archive holds hundreds of programs. We then renormalize so that $\sum_i \alpha_i = 1$. Given $\alpha$, the probability that TTTS measures arm $i$ has a closed form \citep{russo2020simple}:
\begin{equation}
    \psi_i = \alpha_i \Big( \beta + (1 - \beta) \sum_{j \neq i} \frac{\alpha_j}{1 - \alpha_j} \Big).
\end{equation}
The first term corresponds to step 2: arm $i$ is the first draw, which happens with probability $\alpha_i$, and it is kept with probability $\beta$. The second term corresponds to step 3: some other arm $j$ is the first draw, and the resampling loop returns $i$. That loop draws from the posterior conditioned on $j$ not being the argmax, so it returns $i$ with probability $\alpha_i / (1 - \alpha_j)$. Computing $\psi$ exactly removes Monte Carlo noise from the allocation. It also avoids the rejection loop in step 3, which can need very many draws when $\alpha_I$ is close to one.

TTTS is sequential: it updates the posterior after every measurement, so each measurement depends on the ones before it. In meta-evolution, one measurement is a full run on the training tasks with one more seed. These runs are expensive, and we execute them in parallel on a cluster. We therefore use a batched variant with a fixed budget of $B$ reevaluation seeds per generation. At the start of each generation, we compute $\psi$ once from the current posterior over the whole archive, deduplicated by program code. We use the archive rather than only the current population so that programs just outside the top can still be reevaluated. We then draw $B$ arms independently from $\psi$, so program $i$ receives $n_i$ additional seeds, where $(n_1, \dots, n_A) \sim \mathrm{Multinomial}(B, \psi)$. All $B$ seeds run in parallel with the evaluation of that generation's offspring, and when they finish we update $\mu_i$ and $N_i$ for each reevaluated program. This is equivalent to running $B$ steps of TTTS with the posterior held fixed during the batch. Adaptivity is lost within a generation but kept across generations, because each allocation conditions on all reevaluations so far. We use $\beta = 1/2$ and a fixed $\sigma \approx 0.065$, estimated offline by pooling the seed-to-seed variance of fitness within programs from an earlier run. Fixing $\sigma$ lets allocation begin before any program has been evaluated on more than one seed. Finally, TTTS targets identification of the single best program, whereas parent selection draws from the top of the population. In practice, TTTS still concentrates reevaluations on programs with high fitness and uncertain rank, and it spends almost none on programs that are clearly out of contention.
