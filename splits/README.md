# Splits

All files here are task lists (one dataset name per line) used by the
evolve/eval scripts to pick which SRBench problems to run on. Every split
is deterministically generated by `scripts/problem_difficulty.py` from the
SRBench ground-truth results feather (`srbench/results/ground-truth_results.feather`).

Difficulty is defined as the number of (algorithm, noise, trial) tuples in
SRBench that solved each problem symbolically. Problems are ranked hardest
(rank 1) to easiest. The scoring and stratification logic lives in
`compute_problem_difficulty` and `generate_train_val_test_split`.

## Files

### `srbench_all.txt` (133)
The **full** SRBench ground-truth set: 119 Feynman + 14 Strogatz. This file
is hand-maintained (not generated by `problem_difficulty.py`) and is the
**only** split that includes the 3 `EXCLUDED_DATASETS`
(`feynman_I_26_2`, `feynman_I_30_5`, `feynman_test_10`). Those three have
inverse-trig ground truths (`arcsin` / `arccos`) that are unreachable with
our operator set (`+ - * /`, `sin cos exp log sqrt square`), so a symbolic
GT match is impossible for them — they will run and fit a high-R²
approximation but always score `gt_match = 0`. They are included here so
that full-SRBench evaluations report against the canonical 133-task
denominator (comparable to published SRBench numbers).

Every *other* split below is generated from the SRBench difficulty feather
by `problem_difficulty.py` and explicitly drops `EXCLUDED_DATASETS`, so the
130 solvable tasks are what gets stratified into train/val/test, A/B, hard,
and barely-unsolvable splits.

### `train.txt` / `val.txt` / `test.txt` (20 / 20 / 90)
Stratified-by-difficulty split of the 130 solvable tasks. Problems are sorted hardest
→ easiest, divided into difficulty strata, and assigned so that all three
splits have matching difficulty distributions. Within each file, tasks
remain in difficulty order (hardest first). Generated by
`generate_train_val_test_split`.

### `bb_train.txt` / `bb_val.txt` / `bb_test.txt` (20 / 20 / 82)
The canonical 122 SRBench black-box regression problems listed in
`srbench/docs/csv/blackbox_results_datasets.csv`. Starting from the sorted
dataset names, the Friedman and non-Friedman groups were independently shuffled
with Python's `random.Random(42)`. The first 10 problems from each group went to
train, the next 10 to validation, and the remainder to test. Thus train and
validation each contain 10 Friedman and 10 non-Friedman problems; test contains
42 and 40, respectively. The files are mutually exclusive and exhaustive.

`evolve_pysr.py` recognizes a split containing only canonical black-box names,
uses held-out-R² fitness and the SRBench black-box data protocol automatically,
and accepts `--test-split` for an end-of-run test evaluation:

```
python evolve_pysr.py \
  --split splits/bb_train.txt \
  --val-split splits/bb_val.txt \
  --test-split splits/bb_test.txt
```

The test split is not used for evolution, validation, or final bundle
selection. It is evaluated only after evolution has finished.

### `train_small.txt` / `val_small.txt` (4 / 4)
Evenly-difficulty-spaced subsets of `train.txt` / `val.txt`, for quick
smoke tests. Generated by `generate_subset_split`.

### `train_hard.txt` / `val_hard.txt` / `test_hard.txt` (20 / 20 / 90)
"Hard" variant: the top-N hardest problems are distributed across the three
splits via serpentine draft, then a few easier problems are folded into
train/val to keep the difficulty distribution from collapsing entirely.
Generated by `generate_hard_splits`.

### `A.txt` / `B.txt` (65 / 65)
Balanced 50/50 split for A/B comparison experiments. Feynman and Strogatz
problems are each serpentine-drafted by difficulty so both halves have
matched difficulty and dataset-family distributions. Generated by
`generate_balanced_split`.

### `barely_unsolvable.txt` / `barely_unsolvable_val.txt` (20 / 20)

Focused split aimed at the solved→unsolved inflection observed in an
evolve_pysr run on `train.txt`:

1. We ran evolve_pysr against `train.txt` (20 tasks, sorted hardest first)
   and logged which tasks each candidate failed to solve — raw list in
   `out/242356_scratch.txt`, analysis in `scripts/242356_analysis.py`.
2. Tasks 0–7 were always solved, tasks 13+ were essentially always
   unsolved, and tasks 8–12 straddled the flip (task 11 = `feynman_I_44_4`
   was unsolved 28% of the time; task 12 = `feynman_I_38_12` jumped to
   99%).
3. Mapping train.txt indices 8 and 12 back onto the full 130-task
   difficulty ranking yields a contiguous window of difficulty ranks
   56..82 — 27 tasks total, the "barely unsolvable" band.

`barely_unsolvable.txt` (train, 20) is 20 of those 27 tasks sampled with
even difficulty spacing. `barely_unsolvable_val.txt` (val, 20) contains
the 7 band tasks not in train, plus 7 tasks immediately harder than the
band (ranks 49..55) and 6 tasks immediately easier (ranks 83..88). Train
and val are mutually exclusive. Generated by
`generate_barely_unsolvable_splits` — re-run with:

```
python scripts/problem_difficulty.py --barely-unsolvable
```

### `barely_unsolvable_val2.txt` (20)
Alternate validation split for the barely-unsolvable experiments: 20
tasks sampled uniformly at random from `srbench_all.txt` minus
`barely_unsolvable.txt` (no difficulty stratification). Disjoint from
`barely_unsolvable.txt`; may overlap with `barely_unsolvable_val.txt`.

### `parity_outliers.txt` (5)
Hand-picked SRBench tasks where PyPySR and PySR disagreed during the
parity-debugging effort (commit 1989425, see `parity_debug_log.md`).
Used as a focused split for `scripts/test_pypysr_vs_pysr_srbench*.py`.

### `neuron_all.txt` / `neuron_loocv1.txt` ... `neuron_loocv6.txt`

The six fully-observable NeuronBench vector-field tasks and their deterministic
leave-one-out training splits.  LOOCV indices follow the order in
`neuron_all.txt`: `z_rebound`, `h_sag`, `na_fatigue`, `ca_rebound`, `d_type`,
and `textbook_M`.  Each LOOCV file therefore contains the other five tasks.
Use these with `evolve_pysr.py --domain neuron`.

### `neuron_first1.txt` / `neuron_first2.txt`

Focused NeuronBench training splits containing the first one or first two
tasks in `neuron_all.txt`, respectively. Use these to compare training on a
small fixed task subset against the leave-one-out runs.

### `boolformer_noisy_train.txt` / `boolformer_noisy_val.txt` / `boolformer_noisy_test.txt` (24 / 48 / 100)

Fixed, mutually exclusive target functions for adapting PySR to Boolformer's
noisy Boolean synthesis distribution. Train and validation are balanced over
requested support sizes 1..6 (4 and 8 targets per size); test is a fresh
100-target IID draw. Each evaluation seed redraws the observations but not the
target: 30..300 random-walk points over up to 126 variables, input/output flip
probability 0..0.10 on the fit sample, and a clean continuation for scoring.
Use these with `--domain boolformer`.

### `pmlb_classification.txt` (31)

The 31 binary PMLB datasets displayed in Boolformer's classification
comparison. The `pmlb_classification:` prefix selects the paper's Boolformer
protocol: columns with more than five values are dropped, 3..5-valued columns
are one-hot encoded, training is capped at 600 rows after a 75/25 seeded
shuffle, fewer than 120 Boolean features are required, and scoring uses the
untouched held-out rows. Deprecated PMLB
names resolve through the repository's existing `_deprecated_*` fallback.

## Regenerating

All writes go to `splits/` and each split family is opt-in, so running the
script only (re)generates what you explicitly ask for. From the repo root:

```
python scripts/problem_difficulty.py --write-train-val-test  # train/val/test
python scripts/problem_difficulty.py --write-small           # train_small/val_small (implies TVT compute)
python scripts/problem_difficulty.py --write-ab              # A/B
python scripts/problem_difficulty.py --hard-split            # *_hard
python scripts/problem_difficulty.py --barely-unsolvable     # barely_unsolvable(_val)
```

With no flags, the script just prints the difficulty ranking without
touching any files.
