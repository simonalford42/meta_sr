# Splits

All files here are task lists (one dataset name per line) used by the
evolve/eval scripts to pick which SRBench problems to run on. Every split
is deterministically generated by `scripts/problem_difficulty.py` from the
SRBench ground-truth results feather (`srbench/results/ground-truth_results.feather`).

Difficulty is defined as the number of (algorithm, noise, trial) tuples in
SRBench that solved each problem symbolically. Problems are ranked hardest
(rank 1) to easiest. The scoring and stratification logic lives in
`compute_problem_difficulty` and `generate_train_val_test_split`.

## Files

### `srbench_all.txt` (130)
All SRBench datasets used in our runs (Feynman + Strogatz, minus
`EXCLUDED_DATASETS` defined in `problem_difficulty.py`).

### `train.txt` / `val.txt` / `test.txt` (20 / 20 / 90)
Stratified-by-difficulty split of the full 130. Problems are sorted hardest
→ easiest, divided into difficulty strata, and assigned so that all three
splits have matching difficulty distributions. Within each file, tasks
remain in difficulty order (hardest first). Generated by
`generate_train_val_test_split`.

### `train_small.txt` / `val_small.txt` (4 / 4)
Evenly-difficulty-spaced subsets of `train.txt` / `val.txt`, for quick
smoke tests. Generated by `generate_subset_split`.

### `train_hard.txt` / `val_hard.txt` / `test_hard.txt` (20 / 20 / 90)
"Hard" variant: the top-N hardest problems are distributed across the three
splits via serpentine draft, then a few easier problems are folded into
train/val to keep the difficulty distribution from collapsing entirely.
Generated by `generate_hard_splits`.

### `A.txt` / `B.txt` (65 / 65)
Balanced 50/50 split for A/B comparison experiments. Feynman and Strogatz
problems are each serpentine-drafted by difficulty so both halves have
matched difficulty and dataset-family distributions. Generated by
`generate_balanced_split`.

### `barely_unsolvable.txt` / `barely_unsolvable_val.txt` (20 / 20)

Focused split aimed at the solved→unsolved inflection observed in an
evolve_pysr run on `train.txt`:

1. We ran evolve_pysr against `train.txt` (20 tasks, sorted hardest first)
   and logged which tasks each candidate failed to solve — raw list in
   `out/242356_scratch.txt`, analysis in `scripts/242356_analysis.py`.
2. Tasks 0–7 were always solved, tasks 13+ were essentially always
   unsolved, and tasks 8–12 straddled the flip (task 11 = `feynman_I_44_4`
   was unsolved 28% of the time; task 12 = `feynman_I_38_12` jumped to
   99%).
3. Mapping train.txt indices 8 and 12 back onto the full 130-task
   difficulty ranking yields a contiguous window of difficulty ranks
   56..82 — 27 tasks total, the "barely unsolvable" band.

`barely_unsolvable.txt` (train, 20) is 20 of those 27 tasks sampled with
even difficulty spacing. `barely_unsolvable_val.txt` (val, 20) contains
the 7 band tasks not in train, plus 7 tasks immediately harder than the
band (ranks 49..55) and 6 tasks immediately easier (ranks 83..88). Train
and val are mutually exclusive. Generated by
`generate_barely_unsolvable_splits` — re-run with:

```
python scripts/problem_difficulty.py --barely-unsolvable
```

## Regenerating

All writes go to `splits/` and each split family is opt-in, so running the
script only (re)generates what you explicitly ask for. From the repo root:

```
python scripts/problem_difficulty.py --write-train-val-test  # train/val/test
python scripts/problem_difficulty.py --write-small           # train_small/val_small (implies TVT compute)
python scripts/problem_difficulty.py --write-ab              # A/B
python scripts/problem_difficulty.py --hard-split            # *_hard
python scripts/problem_difficulty.py --barely-unsolvable     # barely_unsolvable(_val)
```

With no flags, the script just prints the difficulty ranking without
touching any files.
